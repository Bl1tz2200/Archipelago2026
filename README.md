# Archipelago2026 — «Взаимное позиционирование в рое: Змейка»

Программа автономного полёта для инженерного соревнования «Взаимное позиционирование
в рое: "Змейка"» (Москва, 2026). Платформа — квадрокоптер «Сверх.Исследования» (Обрик),
ROS 2, библиотека `sverk_interfaces`.

Дрон-лидер взлетает, считывает ArUco-маркер стартового угла и определяет назначенную
фигуру, обходит полётную зону по меткам со стабилизацией на каждой, зависает на каждом
найденном «яблоке» и отдаёт команду на подъём следующего дрона, после сборки формации
возвращается на стартовую метку.

## Состав репозитория

| Что | Описание | Документация |
|---|---|---|
| [`apple_vision/`](apple_vision) | Распознавание «яблок» по цвету и форме, однократный зачёт каждого. Общая основа для обеих программ лидера | [README](apple_vision/README.md) |
| [`snake_mission/`](snake_mission) | Миссия лидера: поле 7×7, поисковый маршрут с разрежением проходов, полёт по меткам, бюджет сборки, интерфейс роя, симулятор и тесты | [README](snake_mission/README.md) |
| [`head_drone.py`](head_drone.py) | Миссия лидера одним файлом: обход всех 49 узлов, подтверждение метки в узле, центрирование над «яблоком» | [README_RUN.txt](README_RUN.txt) |

### Две программы лидера — в чём разница

Обе решают одну задачу и обе рабочие; выбирается по результатам тестовых полётов.

| | `snake_mission` | `head_drone.py` |
|---|---|---|
| Навигация | по меткам: `frame_id=aruco_<ID>` или наведение по кадру, метраж поля не используется | по координатам `map`, пересчитанным из `--marker-step` |
| Маршрут | проходы разрежены по измеренной полосе обзора: 24 перелёта при полном покрытии | все 49 узлов подряд: 48 перелётов |
| Оценка времени сборки | 139 с из отведённых 180 | ~220 с, в 3 минуты не укладывается |
| Бюджет 3 минуты | таймер, прерывание поиска, возврат на старт | нет |
| Проверка регламента | `search.validate` до взлёта | нет |
| Подъём следующего дрона | интерфейс `SwarmLink` | нет |
| Проверка без железа | симулятор поля и камеры, 29 тестов | нет |
| Объём | пакет, 9 модулей | один файл, 578 строк |

## Быстрый старт

### Без дрона, на любом ноутбуке

```bash
git clone https://github.com/Bl1tz2200/Archipelago2026.git
cd Archipelago2026
pip3 install opencv-python numpy pyyaml

# маршрут поиска, покрытие поля, проверка регламента, оценка времени
python3 snake_mission/tools/plan_preview.py --start 42

# прогон всей миссии в симуляторе: поле, камера, яблоки, полёт
python3 snake_mission/tools/simulate_mission.py --save трек.png

# самопроверка распознавания «яблок» на синтетике
python3 apple_vision/tools/offline_test.py --demo

# тесты
python3 snake_mission/tests/test_snake_mission.py
python3 apple_vision/tests/test_apple_vision.py
```

### На дроне

```bash
# скопировать репозиторий на борт
scp -r Archipelago2026 sverk@<IP_дрона>:~/
ssh sverk@<IP_дрона>          # порт 22, пароль sverk — попадаете сразу в контейнер sverk_ros2

cd ~/Archipelago2026

# 1. пропеллеры сняты: что видит камера над полем меток
python3 snake_mission/tools/marker_check.py --duration 30

# 2. пропеллеры сняты: распознаются ли «яблоки» под камерой
python3 apple_vision/run_apple_detect.py --duration 60

# 3. полёт
python3 snake_mission/run_leader.py       # или: python3 head_drone.py --fly
```

## Что делает программа по шагам

| Этап | Действие | Пункт регламента |
|---|---|---|
| Взлёт | подъём на рабочую высоту (по умолчанию 2.5 м, потолок 3 м) | 2.1.1 |
| Чтение задания | ближайшая к центру кадра **угловая** метка → ID и название фигуры печатаются в терминал | 2.1.1 |
| Замер обзора | сколько рядов меток охватывает кадр на этой высоте | — |
| Маршрут | бустрофедон по меткам, проходы разрежены по полосе обзора, проверка легальности каждого шага | 2.1.3 |
| Поиск | перелёт на соседнюю метку → стабилизация над ней → следующая | 2.1.3 |
| «Яблоко» | зависание на месте, команда рою, ожидание входа дрона в хвост, продолжение | 2.1.2 |
| Возврат | на стартовую метку — оттуда начинается фигура | 2.1.3 |

Поиск заканчивается досрочно, когда засчитаны все три «яблока», и принудительно —
когда истекают отведённые на сборку формации 3 минуты.

## Поле — 49 меток, и ничего в метрах

Полётная зона размечена сеткой **7×7 ArUco-меток**, `ID = row·7 + col`. ID углов из
Приложения 3 регламента — это ровно четыре угла такой сетки:

```
row 6 |  42 43 44 45 46 47 48        42 — Прямоугольник    48 — Трапеция
row 5 |  35 36 37 38 39 40 41
row 4 |  28 29 30 31 32 33 34        границы поля: col, row ∈ 0..6
row 3 |  21 22 23 24 25 26 27
row 2 |  14 15 16 17 18 19 20
row 1 |   7  8  9 10 11 12 13
row 0 |   0  1  2  3  4  5  6         0 — Квадрат           6 — Ромб
         col 0 ............ 6
```

В `snake_mission` метраж поля не используется нигде: узел — это пара индексов, перелёт —
«на соседнюю метку», ширина полосы обзора камеры меряется **в метках**. Метры
появляются только там, где принадлежат самому дрону: его высота из телеметрии при
переводе пикселей в смещение корпуса.

Если физическая раскладка на площадке зеркальная или транспонированная — правятся
`markers.row_major` / `flip_x` / `flip_y` в `snake_mission/config/snake.yaml`, а не код.
Проверяется одним кадром: `snake_mission/tools/marker_check.py`.

## Поисковый маршрут

Проходы через всё поле, между проходами диагональный переход. Шаг между проходами
берётся из измеренной полосы обзора: если камера охватывает соседний ряд меток с каждой
стороны, поле покрывается **тремя проходами вместо семи** — 24 перелёта вместо 48.

```
row 6 | 18 19 20 21 22 23 24        полоса обзора 3 ряда → проходы по рядам 1, 4, 6
row 5 | 17  .  .  .  .  .  .        покрытие 49/49 узлов
row 4 | 16 15 14 13 12 11 10        24 перелёта, оценка 139 с из 180 с
row 3 |  .  .  .  .  .  .  9
row 2 |  .  .  .  .  .  .  8
row 1 |  1  2  3  4  5  6  7
row 0 |  S  .  .  .  .  .  .
```

Ориентация проходов (по строкам или по столбцам) выбирается по той оси, где полоса
обзора шире, а направление — от стартового угла, чтобы возврат был короче. Если маршрут
не влезает в бюджет, миссия **до начала поиска** поднимается выше: чем выше дрон, тем
шире полоса обзора. Во время самого поиска высота не меняется.

## Соответствие регламенту

Проверяется машинно, а не глазами:

| Требование | Как обеспечено |
|---|---|
| Перелёты только между соседними узлами, включая диагональные | `search.validate` проверяет каждый шаг **до взлёта**; невалидный маршрут — отказ от старта |
| В пределах полётной зоны | границы поля = границы сетки меток, `field.inside` |
| Постоянная высота на поиске | высота задаётся один раз до поиска и в цикле обхода не меняется |
| Высота не выше 4 м | конфиг не принимает выше 3 м (защитная сетка 4 м) |
| Каждое «яблоко» засчитывается однократно | подтверждение несколькими кадрами + зачёт по цвету и координате на полу |
| При распознавании цепочка зависает на месте | зависание отдаётся прямо из коллбека распознавания, не дожидаясь конца перелёта |
| Движение не возобновляется, пока дрон не встал в хвост | `SwarmLink.wait_tail_joined`, позиция удерживается всё время ожидания |
| 3 минуты на сборку формации | таймер с момента взлёта, поиск прерывается и лидер идёт на старт |
| Вывод ID маркера и фигуры в терминал | печатается баннером при чтении стартовой метки |

## Настройка на площадке — по порядку

1. **Разложить поле и проверить нумерацию.**
   `python3 snake_mission/tools/marker_check.py --duration 30`, держа дрон над углом поля.
   Смотрим: ID найдены, раскладка совпадает с конфигом, угловая метка распознана,
   полоса обзора не меньше 3 рядов.
2. **Пороги цвета «яблок».** Свет в зале другой — пороги переснимаются на месте:
   `python3 apple_vision/tools/calibrate_hsv.py --grab кадр.png`, подробности в
   [apple_vision/README.md](apple_vision/README.md).
3. **Полоса обзора и высота.** Если `marker_check` показывает 1 ряд — поднять
   `flight.altitude` (или оставить `auto_altitude: true`, миссия поднимется сама).
4. **Прогон маршрута.** `plan_preview.py --start <ID угла>` для всех четырёх углов:
   покрытие 49/49 и оценка времени в пределах 180 с.
5. **Полёт.**

## Настройки

Два файла, оба с комментарием к каждому параметру:

* [`snake_mission/config/snake.yaml`](snake_mission/config/snake.yaml) — высота, скорость,
  словарь ArUco, нумерация поля, допуски стабилизации, разрежение проходов, бюджет сборки.
* [`apple_vision/config/apples.yaml`](apple_vision/config/apples.yaml) — цвета «яблок»
  в HSV, пороги формы и размера, число кадров подтверждения. Используется обеими
  программами лидера.

Частые правки:

| Симптом | Что менять |
|---|---|
| Не укладываемся в 3 минуты | `flight.altitude` выше, `search.max_pass_spacing` больше |
| Дрон долго «ловит» метку | `navigation.center_tolerance` больше, `hold_frames` меньше |
| ID меток не совпадают с узлами | `markers.row_major` / `flip_x` / `flip_y` |
| «Яблоко» не находится | переснять пороги цвета, `min_size_percent` меньше |
| Ложные срабатывания | `registry.confirm_frames` больше, `min_roundness` больше |

## Подключение роя

Взлётом ведомых и подтверждением строя по UWB репозиторий пока не занимается — миссия
лидера отдаёт события через интерфейс:

```python
from snake_mission import LeaderMission

class MySwarm:
    def launch_next(self, index):                    # index — номер яблока, 1..3
        radio.send(f"takeoff:{index + 1}")

    def wait_tail_joined(self, index, timeout):
        return uwb.wait_formation_stable(timeout)    # True — хвост встал на след

LeaderMission(drone, swarm=MySwarm()).run()
```

По умолчанию подставляется заглушка, которая печатает команды и выдерживает паузу, —
чтобы полёт лидера можно было отлаживать в одиночку.

## Проверка без железа

Симулятор подменяет объект дрона: рисует поле меток и «яблоки», считает полёт и отдаёт
кадры той же программе, что полетит на площадке. Через него проверяется вся цепочка —
чтение маркера, измерение полосы обзора, маршрут, стабилизация, зависания, возврат
и посадка.

```bash
python3 snake_mission/tools/simulate_mission.py --start 48 --alt 2.0 --step 1.2 --save трек.png
```

Прогон из всех четырёх углов даёт 3/3 «яблока», возврат и посадку за 150–176 с
модельного времени из отведённых 180.

## Требования

* Python 3.8+, `opencv-python`, `numpy`, `pyyaml`
* на дроне — образ Обрика с ROS 2 и `sverk_interfaces` (внутри контейнера `sverk_ros2`)
* поле ArUco-меток 7×7, словарь `DICT_4X4_50`

## Что не входит

* Полёт назначенной фигуры после сборки: миссия доводит цепочку до стартовой метки
  и (по умолчанию) садится. `land_at_end: false` оставляет лидера висеть на старте.
* Программа ведомых дронов: вход в хвост «по следу», удержание дистанции по UWB.
